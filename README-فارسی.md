# اسکلت Flutter — نرم‌افزار حسابداری کلینیک (نوراژ)

## این چیه؟
یه اسکلتِ حرفه‌ای و کامل از رابط کاربریِ برنامه با Flutter (Dart) که:
- **دقیقاً روی همون معماریِ `modules_config.py`** سوار شده — یعنی هر ۱۳ ماژول
  (خدمات، ویزیت، وکسلر، بیمه، هزینه‌ها، دریافت‌ها، بانک، بستانکاران،
  مطالبات، تنظیمات خدمات، درمانگران، سوپروایزرها، بیماران) از روی **یک فایل
  تنظیمات واحد** (`lib/config/modules_config.dart`) به‌صورت خودکار ساخته می‌شن
  — نه با نوشتنِ صفحه‌ی جدا برای هر کدوم. اضافه‌کردنِ ماژولِ چهاردهم فقط یعنی
  چند خط به اون فایل اضافه کنید.
- ظاهر مدرن با گرادیان، سایه، انیمیشن‌های ساده و کارت‌های آماری — چیزی که
  توی Tkinter اصلاً ممکن نبود.
- ریسپانسیو واقعی: روی صفحه‌ی بزرگ (دسکتاپ) سایدبار ثابته، روی موبایل
  Drawer کشویی می‌شه — **همین یک کد پایه، هم exe ویندوز می‌سازه هم اپ
  اندروید/iOS** (طبق چیزی که خودتون خواستید).
- راست‌به‌چپ و فارسی از پایه (Directionality rtl + فونت وزیرمتن).

## چیزی که هنوز واقعی نیست (عمداً، طبق نقشه‌راهی که قبلاً صحبت کردیم)
- **داده‌ها**: الان از `MockDataService` (داده‌ی نمایشیِ در حافظه) میان، نه
  از یه سرور واقعی. چون بک‌اند فاز ۲ (FastAPI + PostgreSQL + WebSocket که
  قبلاً طراحیش رو گفتم) هنوز نوشته نشده. `lib/services/api_service.dart`
  از الان با همون قرارداد (متدها) آماده‌ست؛ وقتی بک‌اند حاضر شد، فقط یک
  خط توی `main.dart` عوض می‌شه (`MockDataService` → `ApiService`) و بقیه‌ی
  UI دست‌نخورده می‌مونه.
- **لایسنس/اشتراک**: هنوز به `licensing.py`/پلاگین وردپرسی وصل نشده.
- **تاریخ شمسی**: کامل شد — `lib/widgets/jalali_date_picker.dart` یه
  انتخابگر تقویمِ شمسیِ واقعی با پکیج `shamsi_date` هست (ماه‌ها، روزهای
  هفته از شنبه، پیمایش ماه/سال) و توی فرم افزودن/ویرایش هر ماژول وصل شده.
- **فونت وزیرمتن**: فایل‌های واقعیِ `.ttf` را باید خودتان از
  https://github.com/rastikerdar/vazirmatn دانلود و در `assets/fonts/`
  بگذارید (این محیط به گیت‌هاب برای دانلود فایل باینری فونت دسترسی نداشت).

## چطور اجراش کنم؟ (برای تست حین توسعه)
پیش‌نیاز: [نصب Flutter SDK](https://docs.flutter.dev/get-started/install) روی
سیستم خودتون (ویندوز/مک/لینوکس).

```bash
# ۱. یه پروژه‌ی خالیِ فلاتر بسازید (فایل‌های android/ios/windows و... رو می‌سازه)
flutter create --org ir.nuraazh --project-name clinic_accounting clinic_app
cd clinic_app

# ۲. محتوای پوشه‌ی lib/ و فایل pubspec.yaml همین تحویل رو جایگزین نسخه‌ی
#    پیش‌فرضی که flutter create ساخت بکنید (پوشه‌های android/ios/windows رو دست نزنید)
#    بقیه‌ی فایل‌ها (build_windows.bat, build_android.bat, installer.iss,
#    .github/, test/) رو هم همون کنار پوشه‌ی lib کپی کنید.

# ۳. فونت وزیرمتن رو دانلود و در assets/fonts/ بذارید (بالا توضیح داده شد)

# ۴. نصب وابستگی‌ها
flutter pub get

# ۵. اجرا روی دسکتاپ ویندوز
flutter run -d windows

# یا اجرا روی موبایل (با شبیه‌ساز باز یا گوشی وصل با USB debugging)
flutter run
```

## ساختِ نسخه‌ی نهاییِ نصب‌شدنی برای تحویل به مشتری (دقیقاً مثل روندی که با پایتون داشتید)
اینجا دیگه با `flutter run` کاری ندارید — اون فقط برای تستِ خودتونه. برای
گرفتنِ فایلی که بشه دستِ مشتری داد:

### نسخه‌ی ویندوز (exe)
```
build_windows.bat
```
این اسکریپت رو (با دابل‌کلیک یا از ترمینال) اجرا کنید. اگه موفق شد،
خروجی رو اینجا پیدا می‌کنید: `build\windows\x64\runner\Release\`

این پوشه به‌تنهایی هم قابل‌اجراست (مثل پوشه‌ی `dist\ClinicAccounting` قبلی)،
ولی برای یه تجربه‌ی نصبِ حرفه‌ای («Next, Next, Install»)، طبق همون روالی که
قبلاً با Inno Setup داشتید:

1. اگه از قبل Inno Setup نصب ندارید، از innosetup.org دانلود کنید (رایگان).
2. فایل `installer.iss` رو با Inno Setup باز کنید.
3. کلید **Compile** (یا F9) رو بزنید.
4. خروجی: یه فایل تکی به اسم **`ClinicAccounting-Setup.exe`** توی پوشه‌ی
   `Output` — دقیقاً همین یه فایل رو به مشتری بدید.

نکته: اگه اسم پروژه رو موقع `flutter create` چیزی غیر از `clinic_accounting`
گذاشتید، خط `MyAppExeName` توی `installer.iss` رو با اسم واقعیِ فایل exe
(داخل پوشه‌ی Release) هماهنگ کنید.

### نسخه‌ی موبایل (APK اندروید)
```
build_android.bat
```
خروجی: `build\app\outputs\flutter-apk\app-release.apk` — همین یه فایل رو
می‌تونید مستقیم برای نصب روی گوشیِ هرکسی بفرستید (باید یه‌بار روی گوشیِ
گیرنده، «نصب از منابع ناشناس» رو فعال کنه).

### اگه هنوز Flutter رو نصب نکردید
یادتونه گفتیم گیت‌هاب می‌تونه همه‌ی این کارها رو خودش، روی سرورهای خودش،
انجام بده؟ فایل `.github/workflows/flutter-ci.yml` که در همین پروژه هست
دقیقاً همین کار رو می‌کنه — با هر push، هم APK هم نسخه‌ی ویندوز رو خودکار
می‌سازه و به‌عنوان Artifact قابل‌دانلود می‌ذاره، بدون اینکه شما چیزی روی
سیستم خودتون نصب کرده باشید.

## نحوه‌ی اتصال به گیت‌هاب برای تست خودکار (توصیه‌شده تا نصب Flutter آماده بشه)
چون شما هنوز Flutter رو نصب نکردید، بهترین راه اینه که بذارید **گیت‌هاب خودش**
تست/آنالیز/ساختِ برنامه رو با سرورهای خودش انجام بده (کاملاً رایگان برای
مخزن عمومی یا خصوصیِ کوچیک). فایل `.github/workflows/flutter-ci.yml` که در
همین پروژه هست، این کار رو خودکار انجام می‌ده.

```bash
# داخل پوشه‌ی clinic_flutter:
git init
git add .
git commit -m "نسخه‌ی اولیه‌ی اسکلت Flutter"

# یه ریپوی خالی (بدون README/gitignore) توی گیت‌هاب بسازید، بعد:
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git push -u origin main
```

بعد از push:
1. برید توی صفحه‌ی ریپو، تب **Actions** رو باز کنید.
2. یه ران به اسم «Flutter CI» می‌بینید که خودکار شروع شده.
3. اگه سبز شد یعنی کد بدون خطای آنالیز/تست کامپایل و اجرا شده.
4. اگه قرمز شد، روی همون ران کلیک کنید، لاگ خطا رو کپی کنید و همینجا برام
   بفرستید تا اصلاحش کنم.
5. بعد از موفقیت، توی تب Actions، پایین همون صفحه‌ی ران، بخش **Artifacts**
   دو فایل قابل‌دانلود می‌بینید: `clinic-app-debug-apk` (نسخه‌ی آزمایشیِ
   اندروید، نصب‌شدنی مستقیم روی گوشی) و `clinic-app-windows` (نسخه‌ی
   اجرایی ویندوز) — یعنی **حتی قبل از اینکه Flutter رو روی سیستم خودتون
   نصب کنید، می‌تونید از همین الان یه نسخه‌ی واقعی و قابل‌نصب از برنامه
   رو دانلود و تست کنید.**

## فایل‌های کلیدی برای ادامه‌ی کار
- `lib/config/modules_config.dart` — تعریف همه‌ی ماژول‌ها (این‌جا رو با
  خیال راحت برای ماژول جدید ویرایش کنید)
- `lib/services/api_service.dart` — قرارداد اتصال به بک‌اند واقعی
- `lib/widgets/dynamic_form.dart` / `dynamic_table.dart` — موتور فرم/جدولِ
  پویا (قلب برنامه)
- `lib/widgets/jalali_date_picker.dart` — انتخابگر تقویم شمسی
- `test/formatters_and_config_test.dart` — تست‌های واحد (با `flutter test`
  یا خودکار توسط GitHub Actions اجرا می‌شن)
- `.github/workflows/flutter-ci.yml` — تنظیمات تستِ خودکار روی گیت‌هاب

## احرازِ هویتِ کاربران و حسابرسی (Audit Trail)
- ورود به برنامه دیگر با تایپِ آزادِ اسم نیست — باید نام‌کاربری/رمزی که در
  ماژولِ «کاربران و دسترسی‌ها» تعریف کرده‌اید وارد شود (کاربرهای نمونه:
  `admin`/`admin123`، `sara.k`/`1234`، `nilofar.r`/`1234`).
- هر رکوردی که در هر ماژولی (خدمات، ویزیت، دندانپزشکی، هرچی) ثبت یا ویرایش
  می‌شود، خودکار مهرِ «چه کسی، چه زمانی» می‌خورَد. این اطلاعات با دکمه‌ی
  🛈 کنار هر ردیف قابل‌مشاهده است، ولی چون از اول جزوِ فیلدهای تعریف‌شده‌ی
  ستون‌های جدول نیست، نه در جدولِ اصلی و نه در هیچ فیشِ چاپیِ بیمار ظاهر
  نمی‌شود — دقیقاً طبق چیزی که خواستید.
- **نکته‌ی امنیتیِ مهم:** رمزها در این نسخه (چون هنوز بک‌اند واقعی نداریم)
  به‌صورت متنِ ساده در حافظه نگه داشته می‌شوند — فقط برای نمایش و تستِ
  رابط کاربری مناسب است. در فاز ۲ (بک‌اندِ FastAPI)، احرازِ هویت باید
  حتماً سمتِ سرور، با رمزِ هش‌شده (bcrypt یا مشابه) و روی HTTPS انجام شود.

## نکته‌ی مهم درباره‌ی محدودیت من (شفاف بگم)
من توی همین محیط، مستقیماً امکان اجرا/کامپایل Flutter رو ندارم — چون ابزار
Flutter برای دانلود موتور و Dart SDK به دامنه‌ی `storage.googleapis.com`
نیاز داره که توی سندباکس من بسته‌ست (حتی با اینکه به خودِ گیت‌هاب دسترسی
دارم). پس این کد رو با دقت و با مرور دستی نوشتم و منطقش رو با مستندات
رسمی پکیج‌ها (مثل shamsi_date) چک کردم، ولی تضمین صددرصدیِ «بدون هیچ خطای
کامپایل» نمی‌تونم بدم — دقیقاً به همین دلیل، workflow گیت‌هاب رو ساختم تا
اولین تستِ واقعی رو خودِ گیت‌هاب (که دسترسی کامل داره) بگیره و اگه جایی
خطا بود، برام بفرستید اصلاح کنم.
